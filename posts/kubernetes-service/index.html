Service (서비스)

쿠버네티스 클러스터안에 컨트롤러를 이용해서 파드를 띄웠다면,

이제 그 파드들에 접근해보자!

파드는 컨트롤러에 의해 관리되기 때문에 한군데에 고정되어 떠 있지 않고, 클러스터 내를 옮겨다니게 된다.

이 과정에서 노드를 옮기면서 실행되기도 하고 클러스터내의 파드 IP가 변경되기도 하는데,

이렇게 동적으로 변하는 파드들에 고정된 방법으로 접근하기 위해서 사용하는 개념이 쿠버네티스의 서비스(service)이다.

서비스를 사용하게 되면 파드가 클러스터내의 어디에 있는지에 상관없이 고정된 주소를 이용해서 접근이 가능해진다.

그리고 서비스를 통해 클러스터 외부에서 파드에 접근 하는것도 가능하다.

1. 서비스를 위한 고정된 IP가 필요하다.

쿠버네티스는 파드가 항상 건강한 상태이도록 관리하기 때문에, 파드(POD) 하나가 이상이 있어 죽어버리면

자동으로 다시 해당 파드를 띄운다.

따라서 POD는 새로 띄워질 때마다 동적으로 IP를 할당 받게되고, 이 IP변경 가능성이 서비스를 제공하려는 상황에서는 문제가 된다.

서비스를 위해서는 사용자들이 이 서비스를 위해 접근할 고정된 IP 주소가 필요하다.

여러 POD들을 하나의 서비스 객체로 선언할 수 있으며, 이 서비스 객체에는 고정된 IP가 할당된다.

2. 서비스 제공을 위한 POD 집합에 대한 경로를 제공해야 한다.

서비스 객체는 트래픽을 '전달'하는 역할만 수행한다.

실제 서비스를 '수행'하는 객체는 파드이다.

서비스 객체가 할 일은 트래픽이 들어 왔을 때

자신의 서비스와 연관된 POD들까지의 경로를 찾아 트래픽을 전달하는 일이다.

서비스 객체로 묶여진 POD들을 endpoint라고 한다.

서비스 객체는 자신의 endpoint들을 label을 통해 찾아 낸다.

Label은 쿠버네티스 객체들의 특성을 식별하기 위한 key-value 값으로,

쿠버네티스 객체들을 그룹핑 하는 기본 단위이다.

서비스로 트래픽이 들어오면,

서비스와 같은 Label을 갖는 POD endpoint들을 찾아, 이곳으로 트래픽을 전달한다.

Service 구조

Service라는 리소스에 대해 알아보자!🤓

1. 서비스의 종류

서비스 타입 4가지

(1) Cluster IP

타입을 지정하지 않으면 기본으로 설정되며, 클러스터 내부의 파드에서 서비스의 이름으로 접근할 수 있다.

Cluster IP 타입은 아래 그림과 같이 클러스터 내부에서 내부 DNS에 등록한 이름으로 특정 파드 집합에 요청 전송할 수 있게 해준다.

쿠버네티스 Service

(2) NodePort

ClusterIP의 접근 범위뿐만 아니라, 쿠버네티스 클러스터 외부에서도 노드의 IP주소와 포트번호로 접근할 수 있다.

ClusterIp의 기능에 노드 IP 주소에 공개 포트가 열린다. 이를 통해 쿠버네티스 클러스터 외부에서 내부 파드에 요청을 보낼 수 있게 된다.

(3) LoadBalancer

NodePort의 접근 범위뿐만 아니라 쿠버네티크 클러스터 외부에서 대표 IP주소로 접근할 수 있다.

(4) ExternalName

쿠버네티스 클러스터 내의 파드에서 외부 IP 주소에 서비스의 이름으로 접근 할 수 있다.

2-1. Cluster IP 타입의

서비스 매니페스트 작성

Cluster IP : 단일 진입점, 가장작고 가장 기본, virtual IP, service API



vi svc.yml




apiVersion: v1
kind: Service
metadata:
name: web-service
spec:                 # type을 생략하면, ClusterIP가 적용된다
# type: ClusterIP     # 타입지정 해줘도 무방함
  selector:           # service - 백엔드 pod와 연결
    app: web
  ports:
- protocol: TCP
port: 80




kubectl apply -f svc.yml

(2)



vi nginx-deployment.yml




apiVersion: apps/v1
kind: Deployment
metadata:
name: web-deploy
spec:
replicas: 3
selector:
matchLabels:
app: web
  template:
metadata:
labels:
app: web
    spec:
containers:
- name: nginx
        image: nginx:1.16




kubectl apply -f nginx-deployment.yml

서비스 확인 명령어:



kubectl get service

2-2. NodePort 타입의 서비스

클러스트 ip가 생성된 후,모든 워크 노드에 외부에서 접속 가능한 포트 예약, Node까지 확장.

Default NodePort 범위는 30,000-32,767.

ClusterIP의 접근 범위뿐만 아니라,

쿠버네티스 클러스터 외부에서도 노드의 IP주소와 포트번호로 접근할 수 있다.

서비스 생성.



apiVersion: v1
kind: Service
metadata:
name: web-service
spec:                 # type을 생략하여 ClusterIP가 적용된다.
selector:           # service - 백엔드 pod와 연결
    app: web
  ports:
- protocol: TCP
port: 80
type: NodePort

kubectl get pods -o wide 로 Pod가 어디 생성 되었는지 확인 후,

podrk 생성된 IP:아래 포트번호로 웹브라우저 접속해본다.
